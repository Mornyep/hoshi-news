# 星闻公共数据与私人数据分离架构

## 当前生产状态（4.3）

**公开内容层**：所有访问者读取同一份 `news.json`。客户端没有将这些数据当作某位用户的个人资料。公共新闻可在后台由运营方定时采集、核验、一次性生成摘要，供全站复用，但**当前尚未部署后台 AI 新闻处理作业**。

**访客私有层**：本地 `localStorage["starnews:guest:v4.3"]` 只存 `interests`, `saved`, `theme`, `layout`, `motion`, `spoiler`, `largeText`, `onboarded` 等非敏感设置。没有账户、没有跨设备同步，没有 API 密钥；共享浏览器的 localStorage 不是安全身份隔离，用户可以使用临时模式或清除本地设置。

**隐私约束**：任何个人数据或管理员 API 密钥都不得进入公共仓库、GitHub Pages、前端 bundle、静态 JSON 或 Service Worker 缓存。前端不向第三方发送个人设置。分享外观的 URL 只包含 `theme` 和 `layout` 的白名单值，不包含兴趣、收藏、阅读历史或其他私人数据。

## 将来上线“每个人都拥有真正独立账号”时

1. 选择安全身份提供商（例如 Supabase Auth、Firebase Auth 或 Auth.js + 后端），要求登录凭证由可信服务验证，不根据客户端传来的 `user_id` 判定身份。
2. 把个人偏好、收藏、阅读历史单独建成用户私有表，所有数据必须含 `user_id`，为每一次读取和修改执行服务端授权；不要单靠网页隐藏按钮。
3. 若使用 PostgreSQL + Supabase，必须逐表启用 RLS，并使用 `auth.uid()` 对 `SELECT/INSERT/UPDATE/DELETE` 进行限制；禁止默认公开读取所有个人表。测试 Alice 无法读取/写入 Bob 的记录，反之亦然；未登录用户不能读取任何私人记录。
4. API Key 仅放在服务端密钥管理环境中；AI 个人能力使用独立的鉴权用户身份、速率限制和调用成本上限，隔离日志。**不能让所有读者直接借用站长的 ChatGPT Pro 套餐**，不能在公开网页里输入并长久保存私人 API Key。
5. 用户可选择导出和删除账号数据；登录退出应清除个人页面内存，防止共享设备残留。记录隐私政策、删除方式、数据保留和处理目的。
6. 公共新闻快照与私人用户表通过不同 API 分别传递；服务器公共 CDN 缓存仅存公共新闻，私人响应使用 `Cache-Control: private, no-store`，不由 Service Worker 缓存。
7. 在上线前完成跨用户测试、权限审计、越权请求与竞态验证，检查防跨站脚本执行（XSS）、CSRF、CSP、速率限制和所有外部依赖。仅靠客户端 localStorage 无法保证跨账号安全。

## 分阶段 AI 计划

- **阶段一（当前）**：公开、可核验的新闻快照 + 每人设备上的轻量个性化规则。无后台 AI 调用，站长和读者都没有 API 用量。
- **阶段二（未部署）**：通过可信后台定时处理新闻，人工/规则核验，公共 AI 摘要缓存并同步至 JSON。单份结果可供多人使用；时间、来源和不确定性必填。
- **阶段三（未部署）**：用户自愿登录后关联自己的受支持 AI 服务，严格授权、独立额度与数据隔离；不允许匿名用户消耗无限共享额度。

**注意**：本仓库没有激活任何可供外部用户操作的账号后端或按用户的 AI。部署 4.3 仅意味着第一阶段可用。
