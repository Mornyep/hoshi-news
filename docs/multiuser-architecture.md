# PUBLIC AI / 单用户数据隔离规则

## 已实施（4.4）
- 站点公开新闻与 AI 结果分别来自 `news.json` 和 `ai-briefs.json`。生成任务只访问固定的公共 RSS，不读取网页用户资料。`ai-briefs.json` 是所有读者共享的新闻摘要，任何个体偏好不应被写入。
- 游客本地偏好存放在浏览器 `localStorage["starnews:guest:v4.3"]`；不同浏览器配置隔离，但**同设备同浏览器并非不同账户**。
- UI 通过浏览器端排序区分兴趣，不上传兴趣；公共 AI 简报对所有人相同，只改变当前设备本地显示顺序。
- 由 GitHub Actions 的仓库 Secret 提供模型访问凭证，不将凭证放在 HTML/JS/JSON/Service Worker 缓存、日志和 Git 提交中。无密钥运行则跳过生成。
- 防止模型输入诱导：RSS 标题、摘要不可作为命令；后端校验 source ID，输出链接完全由固定发布者 RSS 产生。模型结果不得用于自动紧急报警。源站数据依然需要编辑核查。

## 尚未实施
- 账号身份、跨设备同步、用户独立 AI 对话、用户模型用量隔离均**尚未上线**。不得在 GitHub Pages 上公开一个无需身份验证的共用 AI 代理接口；一旦遭遇滥用可能迅速消耗免费的后台额度。

## 真正的多用户云端化最低条件
1. 使用安全认证（如 Supabase Auth）并验证每次请求的会话身份，不信任客户端自行提供的用户 ID。
2. 个人收藏、历史、偏好使用单独的用户私有表，Postgres/Supabase 启用 RLS，按 `auth.uid()` 逐条授权 `SELECT/INSERT/UPDATE/DELETE`。
3. 创建两个独立用户做越权测试：A 无法查、写、改、删除 B 的任何数据；登出后必须清除内存缓存和敏感状态。
4. 公共 CDN 缓存仅存公共新闻及公共 AI；用户私有响应 `Cache-Control: private, no-store`，不得被公开 Service Worker 缓存。
5. 若实现自带 API / BYOK，必须经过用户明确授权、后台安全代理、每用户额度及速率控制，不允许公共分享链接泄露密钥。
6. 提供导出、删除、隐私公告和明确的数据处理目的；外部 AI 服务的保留策略必须单独提示。
